# IDIS 복리후생 시스템 — 관리자 1차 명세

관리자 기능 1차(0~5단계)까지 구현된 규칙을 정리한 문서다.
화면 시안은 Figma `IDIS 복리후생 시스템` 그룹을 따른다.

- 서버: Spring Boot 4.1 / Java 21 / Thymeleaf / MySQL
- 세션 기반 인증(이름 + 전화번호), 세션 유지 30일
- **역할·재직 여부·대상 구분은 세션 값이 아니라 매 요청 DB 를 다시 읽어 판단한다.**
  세션이 오래 살아 있어 그사이 퇴사·권한 변경이 반영되어야 하기 때문이다.

---

## 1. 엔티티

### Employee (PK `empNo`)

| 필드 | 설명 |
|---|---|
| `empNo` | 사번. PK, 수정 불가 |
| `name` | 이름 |
| `phone` | 전화번호. 로그인 키라 전체에서 유일 |
| `type` | **구분**. `DIRECT`(직접직) / `INDIRECT`(간접직) |
| `department` | 부서 (nullable) |
| `role` | `EMPLOYEE` / `ADMIN` |
| `hireDate` | 입사일 (nullable) |
| `resignDate` | 퇴사일. 재직 중이면 null |
| `active` | 재직 여부 |
| `superAdmin` | 슈퍼 관리자. 역할을 바꿀 수 있는 유일한 계정 |
| `pinHash` | 관리자 PIN 의 BCrypt 해시 (nullable). `EMPLOYEE` 는 null |
| `pinChangeRequired` | 발급·초기화 직후 true. 본인이 바꿔야 관리자 화면에 들어간다 |
| `pinFailCount` | 연속 실패 횟수. 성공하면 0 |
| `pinLockedUntil` | 잠금 해제 시각 (nullable) |

> `empNo` 가 사번, `type` 이 구분이다. 별도 컬럼을 만들지 않았다.

**퇴사는 물리 삭제하지 않는다.** `resign(date)` 가 `resignDate` 를 남기고 `active = false` 로 바꾼다.

**PIN 원문은 어디에도 남기지 않는다.** 해시만 저장하고, 로그·예외 메시지에 값을 넣지 않는다.

### Form

| 필드 | 설명 |
|---|---|
| `title` / `description` | 제목·안내 문구 |
| `target` | 대상 구분. `ALL` / `DIRECT` / `INDIRECT` |
| `targetDepartments` | 대상 부서 (다대다). **비어 있으면 전체 부서** |
| `startAt` / `endAt` | 시작·마감 시각. 둘 다 nullable |
| `status` | `DRAFT` / `OPEN` / `CLOSED` |
| `deletedAt` | 소프트 삭제 |
| `questions` | 질문 목록 (cascade, orphanRemoval) |

### Question / Choice

`Question` 은 `type`, `title`, `required`, `sortOrder`, `config`(JSON) 를 갖는다.
`Choice` 는 `content`, `imagePath`(이미지 선택 전용), `sortOrder`.

### Response / Answer

`(form_id, emp_no)` 유일 — 1인 1응답. 수정하면 `editedAt` 을 남기고 답변만 갈아끼운다.

## 2. 폼 대상 조건

**구분 AND 부서** 로 판단한다. 판정은 `Form.includes(Employee)` **한 곳**에만 있고,
사용자 홈 목록 / 상세 접근 검사 / 관리자 화면의 대상 인원 계산이 모두 이 메서드를 쓴다.
두 벌로 나뉘면 "홈에는 보이는데 대상 인원에는 안 잡히는" 불일치가 생긴다.

```
대상이다  =  (target == ALL 또는 target == 직원의 type)
          AND (targetDepartments 가 비었거나, 직원의 부서가 그 안에 있음)
```

| target | targetDepartments | 대상 |
|---|---|---|
| ALL | 비었음 | 전 직원 |
| DIRECT | 비었음 | 직접직 전원 |
| ALL | 개발팀, 디자인팀 | 두 팀 전원 |
| DIRECT | 개발팀 | 개발팀의 직접직만 |

대상 인원(응답률 분모)은 **지금 재직 중인** 직원만 센다. 폼을 만들 때와 값이 달라질 수 있다.

## 3. 질문 타입과 config 스키마

`Question.config` 는 JSON 이고, 타입마다 쓰는 키가 정해져 있다.
값이 없으면 컬럼이 `NULL` 이다. 모르는 키는 무시하므로 나중에 키가 늘어도 예전 폼이 깨지지 않는다.

| 타입 | 화면 | config |
|---|---|---|
| `SHORT_TEXT` | 단답 | 없음 |
| `LONG_TEXT` | 장문 | 없음 |
| `PHONE` | 전화번호 | 없음 |
| `SINGLE_CHOICE` | 단일선택 | 없음 |
| `MULTI_CHOICE` | 다중선택 | `{"maxSelect": 3}` — 없으면 제한 없음 |
| `IMAGE_CHOICE` | 이미지 선택 | `{"multiple": true}` — 없으면 하나만 선택 |
| `DATE` | 날짜 | `{"minDate": "2026-09-01", "maxDate": "2026-09-30"}` — 둘 다 선택 사항 |
| `ADDRESS` | 주소 | 없음 |

`QuestionType` 은 위 8종이 전부다. 편집 화면의 타입 선택, 응답 화면의 렌더링,
DB 의 `question.type` ENUM 이 모두 같은 8종으로 맞춰져 있다.

셋 중 하나라도 어긋나면 편집 화면이 그 질문을 그리지 못하고, 저장할 때
전송되지 않아 DB 에서 사라진다. 타입을 추가할 때는 반드시 셋을 함께 고친다.
편집기가 모르는 타입을 만나면 배너를 띄우고 저장 버튼을 잠근다
(`admin-form-edit.js` 의 `blockUnsupported`).

### 응답 저장 형태

- 선택형: `answer_choice` 에 선택지 id 로 저장. `IMAGE_CHOICE` 도 같다.
- `ADDRESS`: `{"zipcode":"...","address":"...","detail":"..."}` JSON.
  배송업체 전달용 엑셀에서 우편번호를 따로 뽑을 수 있어야 해서 구조를 유지한다.
- `PHONE`: 하이픈을 붙인 형식으로 통일해 저장한다. 화면에서도 입력하면서 하이픈이 붙는다.
- 그 밖: 문자열 그대로.

### 응답 검증

같은 판정을 화면과 서버가 같이 쓴다. 화면에서 막더라도 서버에서 한 번 더 본다.

- 필수 항목 누락
- `maxSelect` 초과 → `'질문 제목' 은 최대 N개까지 선택할 수 있습니다`
- `DATE` 허용 범위 밖 → `'질문 제목' 은 2026-09-01 ~ 2026-09-30 에서 골라주세요`
- `PHONE` 형식 오류 → `'질문 제목' 의 전화번호 형식이 올바르지 않습니다`
  하이픈을 뺀 숫자가 `01` 로 시작하는 10~11 자리여야 한다.
  저장은 직원 전화번호와 같은 하이픈 형식(`010-1234-5678`)으로 맞춘다.

> 검증은 저장 트랜잭션 **밖**에서 돈다. 트랜잭션 안에서 예외로 롤백시키면
> 그 뒤 화면을 다시 그릴 때 지연 로딩이 끊긴다.

### 선택지 이미지

- 저장 위치: `app.upload.dir` (기본 `./uploads`) 아래 `forms/`, DB 에는 경로만 둔다
- 제공 경로: `/uploads/**` — 응답자도 봐야 하므로 관리자 인터셉터가 걸리지 않는다
- 5MB 이하, jpg / png / webp 만. **확장자가 아니라 파일 앞 12바이트로 형식을 판단한다**
- 폼 저장과 분리해 먼저 올린다. 저장이 검증에 걸려도 올린 그림이 날아가지 않는다

## 4. 폼 편집 규칙

- 새 폼은 `OPEN` 으로 만든다. 마감일을 비우면 상시 접수, 날짜만 넣으면 23:59 로 채운다
- 저장하면 질문을 통째로 다시 만든다. 순서 변경·복제·삭제가 한 번에 반영된다
- **응답이 하나라도 있으면 마감일만 바꿀 수 있다.** 화면도 잠그고 서버도 나머지 입력을 무시한다
- 폼 복제는 이번 범위에 없다

### 검증 (저장 시)

| 항목 | 메시지 |
|---|---|
| 제목 없음 | 폼 제목을 입력해주세요 |
| 질문 0개 | 질문을 하나 이상 추가해주세요 |
| 질문 제목 없음 | 질문 N 의 내용을 입력해주세요 |
| 선택지 0개 | 질문 N 의 선택지를 하나 이상 추가해주세요 |
| 빈 선택지 | 질문 N 에 내용이 비어 있는 선택지가 있습니다 |
| 이미지 누락 | 질문 N 의 선택지마다 이미지를 올려주세요 |
| maxSelect 범위 | 질문 N 의 최대 선택 수는 1 이상 M 이하여야 합니다 |
| 날짜 범위 역전 | 질문 N 의 허용 범위가 뒤집혀 있습니다 |
| 없는 부서 | 없는 부서가 대상에 들어 있습니다 |

검증에 걸리면 목록으로 튕기지 않고 **입력한 내용 그대로 편집 화면을 다시 그린다.**

## 5. 직원 엑셀 규칙

컬럼 순서 고정: **사번 / 이름 / 부서 / 구분 / 전화번호 / 입사일**

- `.xlsx` 만. 첫 번째 시트, 1행은 머리글이므로 건너뛴다. 빈 행은 무시
- **사번 기준으로 추가·갱신한다. 파일에 없는 직원은 건드리지 않는다** (전체 교체가 아니다)
- 없는 부서 이름이 나오면 새로 만든다
- **검증과 반영이 분리되어 있다.** 오류가 하나라도 있으면 반영 버튼이 잠기고,
  반영 시점에 다시 검증해서 그사이 바뀐 것까지 막는다

### 행 오류

| 사유 | 조건 |
|---|---|
| 사번 누락 / 파일 내 사번 중복 | |
| 이름 누락 | |
| 구분 누락 / 구분 값 오류 (직접직/간접직) | `직접직`·`간접직`·`DIRECT`·`INDIRECT` 만 허용 |
| 전화번호 누락 / 형식 오류 | `^01[016789]-?\d{3,4}-?\d{4}$` |
| 파일 내 전화번호 중복 / 다른 직원이 쓰는 전화번호 | |
| 입사일 형식 오류 (yyyy-MM-dd) | `/` `.` 구분자와 엑셀 날짜 셀도 받는다 |

내려받기는 양식(예시 1행)과 현재 목록(화면 필터 그대로) 두 가지.
한글 파일명은 RFC 5987 로 인코딩한다.

## 6. 관리자 계정 규칙

### 로그인 흐름

이름+전화번호만 알면 되는 상태로는 전 직원 개인정보와 응답 내역에 닿을 수 있어
`ADMIN` 에게만 한 단계를 더 둔다. 직원 로그인은 그대로다.

```
이름 + 전화번호
   ├─ EMPLOYEE ─────────────────────────────→ 세션 생성 → /forms
   └─ ADMIN
        ├─ pinHash 가 null      → 로그인 불가 ("관리자에게 PIN 발급을 요청해 주세요")
        └─ /login/pin (PIN 6자리)
             ├─ pinChangeRequired → /login/pin/change → 새 PIN 저장 → 세션 생성 → /admin
             └─ 아니면                                              세션 생성 → /admin
```

**세션(`loginUser`)은 PIN 까지 끝난 뒤에만 만든다.** 그 전에는 대기 표시만 세션에 둔다
(`pendingAdminEmpNo`, `pinChangePendingEmpNo`). 인터셉터는 `loginUser` 를 보므로,
PIN 을 통과하지 못한 관리자는 `/admin/**` 에 접근할 수 없다.

### PIN 규칙

| 항목 | 값 |
|---|---|
| 형식 | 숫자 6자리 |
| 저장 | BCrypt 해시 (`$2a$`/`$2b$`/`$2y$` 모두 인식) |
| 잠금 | 연속 5회 실패 시 10분. 남은 시간을 안내 |
| 잠금 중 | PIN 이 맞아도 거부 |
| 성공 시 | 실패 횟수·잠금 해제 |

**발급·초기화는 슈퍼 관리자만.** 직원 수정 모달에서 한다.

- 역할을 `ADMIN` 으로 올릴 때 초기 PIN 6자리가 **필수**. `pinChangeRequired = true` 로 저장
- 이미 `ADMIN` 인 사람은 값을 넣으면 초기화, 비워 두면 그대로
- 역할을 `EMPLOYEE` 로 되돌리면 PIN 관련 값이 전부 지워진다 (`clearPin()`)
- 본인 변경은 관리자 사이드바 하단 `PIN 변경` → 현재 PIN 확인 후 새 PIN

슈퍼 관리자는 시드에 `pinHash` 가 있어야 로그인할 수 있다. 잊었을 때는 DB 에서 직접 넣는다
(`deploy/setup.md` 의 '관리자 PIN 복구').

### 접근 통제

`/admin` 전체가 인터셉터를 지난다. 매 요청 DB 에서 직원을 다시 읽어
재직 중인 `ADMIN` 이 아니면 403.

관리자가 하나도 남지 않으면 아무도 관리자 화면에 못 들어가므로 세 겹으로 막는다.

| 규칙 | 메시지 |
|---|---|
| 역할 변경은 슈퍼 관리자만 | 역할은 슈퍼 관리자만 변경할 수 있습니다 |
| 슈퍼 관리자의 역할 변경 금지 | 슈퍼 관리자의 역할은 변경할 수 없습니다 |
| 슈퍼 관리자 퇴사 금지 | 슈퍼 관리자는 퇴사 처리할 수 없습니다 |
| 본인의 ADMIN 해제 금지 | 본인의 관리자 권한은 해제할 수 없습니다 |
| 본인 퇴사 처리 금지 | 본인은 퇴사 처리할 수 없습니다 |
| 마지막 관리자 강등·퇴사 금지 | 관리자는 최소 1명 이상 필요합니다 |

### 슈퍼 관리자

`superAdmin` 은 **시드로만 넣고 애플리케이션에서는 바꿀 수 없다.**
입력 폼에 그 값이 아예 없어서 켜지지도 꺼지지도 않는다 — 본인도 자기 것을 못 내린다.

**화면에 드러내지 않는다.** 배지나 별도 표기가 없고, 일반 관리자에게는
직원 수정 모달의 역할 칸 자체가 그려지지 않는다(`th:if="${admin.superAdmin}"`).
폼을 직접 만들어 보내는 경우를 위해 서버에서도 다시 막는다.

마지막 관리자 규칙은 **재직 중인** `ADMIN` 만 센다.
이미 퇴사한 관리자 계정을 정리하는 것까지 막으면 안 되기 때문이다.

### 화면 전환

- 사용자 홈 상단의 `관리자` 링크는 `ADMIN` 에게만 보인다 (세션이 아니라 DB 의 role 기준)
- 관리자 사이드바 하단에 `직원 화면으로` 링크, `PIN 변경` 링크

## 7. 뷰포트 기준

| 화면 | 기준 |
|---|---|
| 사용자 | 모바일 우선. 430px(`--shell`) 폭으로 가운데 정렬 |
| 관리자 | **1024px 이상**에서만 쓴다 |
| 관리자 1024~1279px | 사이드바 200px, 직원 요약 카드 2×2 |
| 관리자 1280px 이상 | 사이드바 240px, 요약 카드 한 줄 |

1024px 미만에서는 콘솔을 감추고 도미 캐릭터와 함께
`관리자 페이지는 PC 또는 태블릿 가로 화면에서 이용해 주세요` 안내만 보여준다.
